# 架构说明

CityAgent 围绕“报告原文 → 带来源的结构化结果 → 校验 → 三表交付”组织代码。通用入口与高级推理入口共享部分解析和输出能力，但使用不同的调度及执行记录，不能把一个入口的验证结果直接当作另一个入口的验收。

## 通用文档工作流

`bridge-evidence` 的入口是 `src/bridge_evidence/cli.py`，由 `BridgeEvidenceOrchestrator` 协调处理：

```text
DOC / DOCX
  → 格式适配与转换校验
  → 文档结构及证据解析
  → 信息、病害和建议抽取
  → 可选历史补充与模型工作流
  → 约束检查
  → Word 三表与 JSON 状态
```

| 模块 | 责任 |
|---|---|
| `adapters/`、`parsers/` | 文档转换、转换质量检查、段落及表格解析 |
| `document_ai/` | 文档区域、解析候选、冲突及可选外部解析器 |
| `models/`、`evidence/` | 统一状态、字段来源、病害关系及约束 |
| `agents/`、`runtime/` | 可选模型调用与有界工作流 |
| `history/`、`matching/` | 显式历史资料与关联匹配 |
| `rendering/` | 基本信息、病害、建议的 Word / JSON 输出 |
| `evaluation/`、`telemetry/` | 离线指标和执行事件 |

默认 `llm_mode=off` 使用本地解析与规则。开启在线模式后，模型调用需要服务能力和凭据；缺少必要资源时不能把离线回退伪装成在线成功。历史索引属于显式输入，不能把评测目标标签当成待抽取报告的证据。

## 高级推理工作流

根目录 `run.py` 与 `src/bridge_evidence/contest/` 保留面向可审计推理的实现。核心模块包括：

- `backends.py`：模型清单、资产校验与后端接口。
- `long_document.py`、`chunked_inference.py`：文档快照、任务责任区、分块抽取及合并。
- `run_state.py`、`rsi_runtime.py`：身份绑定、耗时记录、任务日志、锁与调度。
- `execution_audit.py`：执行记录与最终产物审计。
- `facts.py`、`report_qa.py`：结构化事实及带来源的查询。
- `rsi_*.py`：策略包、隔离 worker、候选实验和验收。

`whole` 保留全文生成流程；`chunked` 将报告拆成有明确责任区的任务；`bounded-react` 增加有界修复。`divide-fixed`、`divide-react`、`document-agent` 是独立的高级路径，其配置、依赖和验收条件需要分别检查。

分块流程区分当前任务负责的来源与仅供理解的上下文。来源校验、完整性检查和最终字段检查各有作用：合法 JSON 不意味着字段有来源，字段有来源也不意味着整份报告已覆盖。不同来源位置的重复文字不能只按文字相同而删除。

## 恢复与并发

高级流程使用持久化调用回执及任务检查点。复用结果需要输入、模型、代码、提示和配置等身份匹配；工作目录由锁保护，恢复应在确认旧执行器退出后进行。失败、重试、拆分和复用都应保留证据。

准备、推理与渲染可以在不同报告间重叠。并发容量应通过目标硬件验证，不能仅调高 worker 数就宣称提速。模型调用累计时间与整批墙钟是不同指标，重叠调用不能相加后用作整批耗时。

## RSI 的位置

RSI 作用于推理行动和策略搜索，不在正常推理中训练模型。`--rsi-mode off` 为默认值；`frozen` 使用固定策略，`experimental-online` 用于明确获准的开发实验。

策略候选不能修改执行器、评分、预算和发布规则。实验通过静态检查、隔离执行或影子测试，仍不能单独证明质量提升。正式启用需要独立完整评测及恢复测试证据；质量、处理速度或恢复速度未达发布条件时，应继续使用已验证基线。

## 已知边界

文档中的图片、OLE、公式和图表不都能转化为完整语义。文字提取成功不能替代这些对象的证据验收。跨年判断还依赖桥梁、幅别、构件和位置能否可靠对应。仓库提供校验与实验机制，不附带通用准确率结论或硬件性能保证。
